[CH01-S03] Rust 三大编译期保证
──────────────────────────────────
预计时长：0:50 | 预计字数：230

[00:45] [THREE:rust-shield-trio]
▶ Rust 到底好在哪？三个点。

[PAUSE:0.5]

▶ 第一，零运行时开销。

▶ Rust 没有垃圾回收器，
▶ 没有虚拟机，
▶ 直接编译成机器码。

▶ 性能可以媲美 C 和 C 加加。

▶ 你的 Node.js 服务里有 V8 在帮你管内存，
▶ 但 Rust 不需要，见屏幕左侧动画。

[PAUSE:1.5]

▶ 第二，内存安全由编译器保证。

▶ 悬垂指针，重复释放内存——
▶ 这些错误在 C 和 C 加加里是家常便饭，
▶ 但在 Rust 里，连编译都过不了。

▶ 屏幕中间的盾牌，代表编译器在拦截这些错误。

[PAUSE:1.5]

▶ 第三，并发安全也在编译期验证。

▶ 数据竞争——
▶ 这个并发编程里的老大难问题，
▶ Rust 直接在编译期就把它消灭了。

[PAUSE:1.0]

▶ 这三个保证加在一起，
▶ 就是 Rust 和其他语言，
▶ 最本质的区别。

[PAUSE:2.0]

[04:05] [COMPARE:package.json vs Cargo.toml]
▶ 我们来看 Cargo.toml。
▶ 如果你熟悉 package.json，
▶ 这个文件你几乎一眼能看懂。

[PAUSE:0.8]

▶ name 是包名，
▶ version 是版本号，
▶ edition 是 Rust 的语言版本——
▶ 用 2021 就行。

[PAUSE:0.8]

▶ 下面的 dependencies 区块，
▶ 用来声明第三方依赖。
▶ 就像 package.json 里的 dependencies。

[PAUSE:0.8]

▶ 和 package.json 的区别是，
▶ Cargo.toml 用的是 TOML 格式，
▶ 支持注释，
▶ 用井号开头就行，
▶ 可读性更好。

[PAUSE:1.0]

▶ 还有一个 Cargo.lock，
▶ 类似于 pnpm-lock.yaml。

▶ 对于应用程序，
▶ 必须提交到 git。

▶ 对于库项目，
▶ 可以不提交。

[CH01-S10] 变量不可变设计
──────────────────────────────────
预计时长：0:40 | 预计字数：185

[05:10] [THREE:immutable-lock]
▶ 最后一个概念，变量的不可变性。

[PAUSE:0.8]

[05:14] [CODE:rust:let x = 5 然后强行赋值报错]
▶ 在 Rust 里，let x 等于 5，
▶ 这个 x 是不能修改的，见屏幕代码。

▶ 如果你强行给它赋值——
▶ 编译器会报错：
▶ 「cannot assign twice to immutable variable」
▶ 屏幕上的锁变红了，
▶ 代表编译器把这个修改操作锁住了。

[PAUSE:1.5]

[05:28] [CODE:rust:let mut x = 5 正常运行]
▶ 如果你确实需要修改，
▶ 要显式写 let mut x 等于 5。

▶ mut 是 mutable 的缩写，
▶ 意思是：「我知道我要修改这个变量」。

▶ 屏幕上的锁打开了，绿色通过。

[PAUSE:1.0]

▶ 这种设计的好处是，
▶ 编译器帮你验证意图。

▶ 如果你声明了 mut 但从没修改，
▶ 编译器还会提醒你：
▶ 是不是写多了？

▶ 这类似于 JS 里的 const，
▶ 但语义比 const 更精准。

[PAUSE:2.0]

[CH01-S11] 三个常见坑
──────────────────────────────────
预计时长：0:25 | 预计字数：120

[05:50] [DIAGRAM:card:三张警告卡片依次弹出]
▶ 三个初学者常见的坑。

[PAUSE:0.5]

▶ 第一，cargo run 很慢。
▶ 这是 debug 模式包含了大量调试信息，
▶ 用 cargo build 加 release 参数，
▶ 快得多，体积也小。

[PAUSE:0.8]

▶ 第二，Cargo.lock 要不要提交。
▶ 应用程序必须提交，
▶ 库项目可以不提交。

[PAUSE:0.8]

▶ 第三，rustc 和 cargo 的关系。
▶ cargo 内部会自动调用 rustc，
▶ 你平时只用 cargo 就行，
▶ 几乎不需要直接调 rustc。

[PAUSE:2.0]
