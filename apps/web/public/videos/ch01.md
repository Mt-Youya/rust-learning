  一、章节理解
  
  本章一句话总结

  本章帮助前端工程师建立 Rust 工具链认知——rustup 管工具链、Cargo 管项目，是你进入 Rust 世界的真正入口，而不是语法本身。

  学习目标

  1. 能独立安装 Rust 并验证环境（rustup、rustc、cargo 三命令可用）
  2. 理解 Cargo 是什么，以及它与 npm/webpack 的关系
  3. 能用 cargo new 创建项目并用 cargo run 运行
  4. 理解 Cargo.toml 与 package.json 的对应关系
  5. 知道 Rust 变量默认不可变，mut 是显式意图声明

  核心知识点

  - rustup = Rust 的 nvm（工具链版本管理）
  - rustc = Rust 编译器（通常不直接调用）
  - Cargo = npm + webpack + jest 的合体
  - Cargo.toml = package.json（TOML 格式）
  - let 默认不可变，let mut 显式可变
  - Rust 三大编译期保证：零运行时开销 · 内存安全 · 并发安全

  难点

  - 为什么 Cargo 不等于 npm：Cargo 还内置了构建系统，不需要额外的 webpack/vite
  - rustc 和 cargo 的关系：cargo 调用 rustc，用户几乎不直接用 rustc
  - 变量不可变的设计哲学：不是限制，而是让编译器帮你验证意图
  - println! 为什么有感叹号：宏（macro）和函数的区别，此章不深讲但要点到

  常见误区

  ┌────────────────────────────┬────────────────────────────────────────────────────────────────┐
  │            误区            │                            正确认知                            │
  ├────────────────────────────┼────────────────────────────────────────────────────────────────┤
  │ "我先看语法，后面再装环境" │ 工具链是 Rust 的入口，脱离 Cargo 学 Rust 会很痛苦              │
  ├────────────────────────────┼────────────────────────────────────────────────────────────────┤
  │ "Cargo.lock 不用提交"      │ 应用程序必须提交，库项目可以不提交                             │
  ├────────────────────────────┼────────────────────────────────────────────────────────────────┤
  │ "cargo run 很慢"           │ debug 模式包含大量 debug 信息，--release 快得多                │
  ├────────────────────────────┼────────────────────────────────────────────────────────────────┤
  │ "let 和 const 一样"        │ 不完全等价——Rust 的 const 是编译期常量，let 是运行期不可变绑定 │
  └────────────────────────────┴────────────────────────────────────────────────────────────────┘

  前端类比点

  - rustup ↔ nvm（工具链版本管理，但不完全等价——rustup 还管组件）
  - Cargo.toml ↔ package.json（依赖声明，但 TOML 支持注释）
  - Cargo.lock ↔ package-lock.json / pnpm-lock.yaml
  - cargo build --release ↔ npm run build（生产优化构建）
  - crates.io ↔ npm registry
  - cargo add serde ↔ npm install（类比成立，不完全等价）
  - src/main.rs ↔ src/index.js（程序入口）
  - let x = 5 ↔ const x = 5（不可变绑定，但语义略有差异）

  toolchain（工具链型）— 结构：先演示 → 再解释 → 前端类比 → Cargo 项目实战 → 常见坑 → 小结

  ## 开场 Hook（00:00 - 00:20）

  你有没有遇到过这种情况——
  Node.js 服务跑了几天，内存从 200MB 悄悄涨到了 2GB。
  或者你写了一个 CLI 工具，打包完有 60MB，用户下载要等半天。
  TypeScript 很好，它能帮你在编译期抓住类型错误。
  但它管不了内存，也管不了并发。
  这就是很多前端工程师最终来学 Rust 的原因。

  ---

  ## 第一段：本章目标（00:20 - 00:45）

  在这一章，我们要做三件事。
  第一，装好 Rust 环境。
  第二，搞清楚 Cargo 到底是什么。
  第三，用 Cargo 跑起来你的第一个 Rust 程序。
  我们不急着讲语法，因为真正打开 Rust 世界的钥匙，是工具链。

  ---

  ## 第二段：Rust 三大优势（00:45 - 01:35）

  Rust 到底好在哪？三个点。

  第一，零运行时开销。
  Rust 没有垃圾回收器，没有虚拟机，直接编译成机器码。
  性能可以媲美 C 和 C++。
  你的 Node.js 服务里有 V8 在帮你管内存，但 Rust 不需要。

  第二，内存安全由编译器保证。
  不会出现悬垂指针，不会出现重复释放内存。
  这些错误在 C 和 C++ 里是家常便饭，但在 Rust 里连编译都过不了。

  第三，并发安全也在编译期验证。
  数据竞争这个并发编程里的老大难问题，Rust 直接在编译期就把它消灭了。

  这三个点加在一起，就是 Rust 和其他语言最本质的区别。

  ---

  ## 第三段：安装 rustup（01:35 - 02:15）

  安装 Rust 很简单，核心是安装 rustup。
  rustup 是 Rust 的工具链版本管理器，你可以把它理解成 Rust 版的 nvm。
  nvm 管 Node.js 版本，rustup 管 Rust 版本——这个类比基本成立，但 rustup 功能更多。

  在 macOS 或 Linux 上，打开终端，运行这一行命令：
  curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
  然后按提示操作，选默认安装就行。

  Windows 用户去 rustup.rs 下载 rustup-init.exe。

  安装完成之后，重新打开终端，验证一下：
  rustc --version
  cargo --version
  两行都有版本号，就说明装好了。

  rustup 除了管版本，还可以管组件。
  比如 rustup component add clippy，加上代码检查工具。
  rustup component add rustfmt，加上格式化工具。
  rustup target add wasm32-unknown-unknown，加上 WebAssembly 编译支持。
  这些后面章节用到的时候再装就行。

  ---

  ## 第四段：Cargo 是什么（02:15 - 02:50）

  装好环境之后，我们来认识 Cargo。

  Cargo 是 Rust 的核心工具。
  它同时做了 npm、webpack 和 jest 三件事。
  依赖管理、构建、测试，全在 Cargo 里。
  你不需要额外配一个构建工具，开箱即用。

  学 Rust，先学会用 Cargo，比先背语法有用得多。

  ---

  ## 第五段：cargo new 实战（02:50 - 03:40）

  好，现在我们来创建第一个项目。
  终端输入：cargo new temp-converter
  Cargo 会自动帮你：初始化 git 仓库，创建 src 目录，在里面放好 main.rs。

  用 tree 看一下目录结构：
  Cargo.toml 在根目录，src/main.rs 在里面。
  就这两个核心文件。

  打开 main.rs，里面已经有了一个 Hello World。
  运行 cargo run，Cargo 会先编译，再执行。
  第一次会慢一点，因为要下载工具链。之后就快了。

  ---

  ## 第六段：Cargo.toml 讲解（03:40 - 04:20）

  我们来看 Cargo.toml。
  如果你熟悉 package.json，这个文件你几乎一眼能看懂。

  name 是包名，version 是版本号，edition 是 Rust 的版本——用 2021 就行。
  下面的 dependencies 区块，声明第三方依赖。
  比如要用 serde 这个序列化库，就在这里写 serde = "1"。

  和 package.json 的区别是，Cargo.toml 用的是 TOML 格式，支持注释，可读性更好。

  还有一个 Cargo.lock，类似于 package-lock.json。
  对于应用程序，必须把它提交到 git。
  对于库项目，可以不提交。这和 npm 的规范基本一致。

  ---

  ## 第七段：npm vs cargo 命令对比（04:20 - 04:45）

  来做一个快速对照：
  npm install / pnpm add，对应 cargo add。
  npm run build，对应 cargo build --release。
  npm test，对应 cargo test。
  npm publish，对应 cargo publish，发到 crates.io——那是 Rust 的 npm registry。

  记住这几个命令，你 80% 的日常操作都够了。

  ---

  ## 第八段：变量不可变（04:45 - 05:25）

  最后一个概念，变量的不可变性。

  在 Rust 里，let x = 5，这个 x 是不能修改的。
  如果你强行给它赋值，编译器会报错。
  这个设计类似于 JavaScript 的 const，但不完全一样。

  如果你确实需要修改这个变量，要显式写 let mut x = 5。
  mut 是 mutable 的缩写，意思就是"我知道我要修改这个变量"。

  这种设计的好处是，编译器会帮你验证意图。
  如果你声明了 mut 但从没修改，编译器会提醒你，是不是写多余了。
  强制你明确每一个"变化"。

  ---

  ## 第九段：常见坑（05:25 - 05:50）

  三个初学者常见的坑：

  第一，cargo run 很慢。
  这是因为默认是 debug 模式，包含了大量调试信息。
  用 cargo build --release 会快很多，体积也小得多。

  第二，Cargo.lock 要不要提交。
  应用程序必须提交，保证环境一致。
  库项目可以不提交，因为调用方会锁定自己的版本。

  第三，rustc 和 cargo 的关系。
  rustc 是编译器，cargo 是构建系统，cargo 内部会调用 rustc。
  你平时只需要用 cargo，几乎不需要直接调用 rustc。

  ---

  ## 小结（05:50 - 06:20）

  好，我们来回顾一下这一章。

  rustup，管理 Rust 工具链版本，相当于 nvm。
  Cargo，管理项目、依赖、构建、测试，相当于 npm + webpack + jest。
  Cargo.toml，声明依赖，相当于 package.json。
  let 默认不可变，需要修改要加 mut。

  记住这一句话：rustc 是发动机，Cargo 是整辆车。
