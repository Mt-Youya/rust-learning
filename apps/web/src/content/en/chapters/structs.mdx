## Enums: Algebraic Data Types

Rust's `enum` is far more powerful than in other languages — each variant can carry different types of data:

```rust
enum Shape {
    Circle(f64),                            // radius
    Rectangle(f64, f64),                    // width × height
    Triangle { base: f64, height: f64 },    // named fields
}

impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle(r)              => std::f64::consts::PI * r * r,
            Shape::Rectangle(w, h)        => w * h,
            Shape::Triangle { base, height } => base * height / 2.0,
        }
    }
}
```

## Option: Eliminating null

```rust
// no more "undefined is not a function"
fn find_user(id: u32) -> Option<User> {
    if id == 1 { Some(User::new("Alice".into(), "a@b.com".into())) }
    else { None }
}

// forced to handle both cases
match find_user(1) {
    Some(user) => println!("{}", user.greet()),
    None       => println!("user not found"),
}

// concise syntax
if let Some(user) = find_user(1) {
    println!("{}", user.greet());
}

// chained operations
let name = find_user(1)
    .map(|u| u.username)
    .unwrap_or("anonymous".to_string());
```

<Callout type="insight">
  **Option forces you to handle the 'no value' case** — the compiler won't let you ignore None. This is one of the fundamental reasons Rust is safer than JavaScript.
</Callout>

## The Power of Pattern Matching

`match` is exhaustive — you must handle all cases, or compilation fails:

```rust
let number = 7;
let text = match number {
    1        => "one",
    2..=5    => "two to five",
    6 | 7    => "six or seven",
    n @ 8..= => { println!("large number {}", n); "greater than seven" },
    _        => "other",
};
```

**The power of exhaustiveness**: When you add a new variant to your enum, all `match` expressions will trigger a compile error, reminding you to handle the new case. TypeScript's `switch` cannot do this.
