## Error Handling Philosophy

JavaScript's `try-catch` has a fundamental problem: you never know whether a function might throw unless you read the docs or get burned.

Rust's rule: **operations that can fail must reflect that in the type signature**.

<CompareBlock
  concept="Error Handling"
  jsLabel="TypeScript (try-catch)"
  rustLabel="Rust (Result)"
  js={`// you don't know if this function will throw
async function readFile(path: string): Promise<string> {
  try {
    return await fs.readFile(path, 'utf8');
  } catch (e) {
    throw new Error(\`read failed: \${e}\`);
  }
}`}
  rust={`use std::fs;

// the signature tells you directly: may succeed returning String, or fail returning io::Error
fn read_file(path: &str) -> Result<String, std::io::Error> {
    fs::read_to_string(path)  // ? propagates the error
}

// the caller must handle both cases
match read_file("data.txt") {
    Ok(content) => println!("{}", content),
    Err(e)      => eprintln!("error: {}", e),
}`}
  insight="Result makes errors part of the type. You cannot ignore them — the compiler will remind you. This is the core value of Rust's error handling."
/>

## The ? Operator: Elegant Error Propagation

`?` is like `await` — it eliminates the boilerplate of error propagation:

```rust
use std::io;
use std::fs;

fn read_username() -> Result<String, io::Error> {
    // ?: on success continue, on failure immediately return Err
    let content = fs::read_to_string("username.txt")?;
    Ok(content.trim().to_string())
}

// chained ? operations
fn parse_config() -> Result<Config, io::Error> {
    let json = fs::read_to_string("config.json")?;
    let config: Config = serde_json::from_str(&json)
        .map_err(|e| io::Error::new(io::ErrorKind::InvalidData, e))?;
    Ok(config)
}
```

## Custom Errors: thiserror

```toml
[dependencies]
thiserror = "1"
anyhow = "1"
```

```rust
use thiserror::Error;

#[derive(Error, Debug)]
enum AppError {
    #[error("IO error: {0}")]
    Io(#[from] std::io::Error),

    #[error("parse error (line {line}): {msg}")]
    Parse { line: usize, msg: String },

    #[error("user {0} not found")]
    NotFound(String),
}

// ? automatically converts io::Error to AppError::Io
fn process_file(path: &str) -> Result<Vec<Record>, AppError> {
    let content = std::fs::read_to_string(path)?;  // io::Error → AppError::Io
    parse_records(&content)
}
```

<Callout type="tip">
  **Use thiserror for library code**: define precise error types so callers can `match` different cases.<br />
  **Use anyhow for application code**: propagate errors quickly with useful context.
</Callout>

## anyhow: Application-Level Error Handling

```rust
use anyhow::{Context, Result};

fn load_app() -> Result<App> {
    let config = fs::read_to_string("config.json")
        .context("config.json not found")?;

    let settings: Settings = serde_json::from_str(&config)
        .context("config file format error")?;

    App::init(settings).context("application initialization failed")
}
```
