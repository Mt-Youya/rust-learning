## Rust's Built-in Testing: No Extra Framework Needed

<CompareBlock
  concept="Unit Tests"
  jsLabel="TypeScript (Jest)"
  rustLabel="Rust (built-in)"
  js={`// package.json: "jest": "^29.0.0"
import { add } from './math';

describe('add', () => {
  it('adding two positive numbers', () => {
    expect(add(2, 3)).toBe(5);
  });
  
  it('negative numbers', () => {
    expect(add(-1, -2)).toBe(-3);
  });
});`}
  rust={`// written directly in the source file, no packages needed
pub fn add(a: i32, b: i32) -> i32 { a + b }

#[cfg(test)]  // only compiled during testing
mod tests {
    use super::*;

    #[test]
    fn adding_two_positive_numbers() {
        assert_eq!(add(2, 3), 5);
    }

    #[test]
    fn negative_numbers() {
        assert_eq!(add(-1, -2), -3);
    }
}`}
  insight="Tests in Rust are part of the language, not a third-party library. cargo test automatically discovers and runs all #[test] functions, including code examples embedded in documentation."

## Async Tests

```rust
#[tokio::test]
async fn test_api_endpoint() {
    let app = create_test_app().await;
    
    let response = app
        .oneshot(Request::builder()
            .uri("/api/posts")
            .body(Body::empty())
            .unwrap())
        .await
        .unwrap();
    
    assert_eq!(response.status(), StatusCode::OK);
}
```

## SQLx Tests: Automatic Rollback

```rust
#[sqlx::test]
async fn test_create_user(pool: PgPool) {
    // pool is a test-only connection that automatically rolls back after the test
    let user = create_user(&pool, "test@example.com", "testuser", "hash")
        .await
        .unwrap();
    
    assert_eq!(user.email, "test@example.com");
    assert!(user.id.to_string().len() > 0);
}
// database state is automatically restored whether the test passes or fails
```

## Doc Tests: Keep Examples Always Correct

```rust
/// Computes the sum of two numbers.
///
/// # Examples
///
/// ```
/// let result = my_crate::add(2, 3);
/// assert_eq!(result, 5);
/// ```
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

`cargo test` runs code blocks inside documentation, ensuring examples are always up-to-date and correct.

## Development Toolchain

```bash
# code quality check (stricter than the compiler)
cargo clippy -- -D warnings   # treat warnings as errors

# enforce consistent formatting
cargo fmt
cargo fmt --check             # check only, used in CI

# generate and open documentation
cargo doc --open

# scan for security vulnerabilities
cargo audit

# re-run automatically on file changes
cargo watch -x test
cargo watch -x 'clippy -- -D warnings'
```

<Callout type="tip">
  Run in CI: `cargo fmt --check && cargo clippy -- -D warnings && cargo test` — three commands to guarantee code quality.
</Callout>
